# CERSAI SI batch file: row and column mapping

This document explains how to fill every row and column of the **CERSAI 2.0 security-interest (SI) registration batch file** for Anand Rathi Global Finance Ltd (ARGFL). The batch file is a pipe-separated (`|`) `.DAT` text file:

- **Row 1 (FH):** written once per file.
- **Then, for each collateral:**
  - one **SI** row;
  - one **IMM** row for the property;
  - one **BOR** row per borrower;
  - one **CHG** row for the charge holder.

Every row's field list follows `Output Excel Description/CERSAI2_SIRegistration_BatchFormatDescription.xlsx` (sheets `introduction`, `si`, `immovable_asset`, `borrower`, `charge_holder`).

**Sources used:**

| Source | File | Provides |
|---|---|---|
| LMS borrower extract | `Input data/CKYC/CKYC.xlsx` | Borrowers: name, constitution, PAN, dates of birth / incorporation, mobile, email, address |
| LMS collateral extract | `Input data/COLLATERAL/COLLATERAL.xlsx` | Loans, collaterals, owners, property address and PIN, sanctioned amount |
| Legal title reports | `Input data/Legal/<Application number>_<Collateral ID>.pdf` | The type of mortgage, plus property details missing from the LMS extracts |
| CERSAI masters (v29.3) | `Master data/CERSAI2.0_Masters.xls` | Codes: SI type, asset type and sub-type, area unit, borrower type, gender, PIN → district → state, city |
| Required details | `Output data/<batch>/2 Required details_<batch>.xlsx`, generated by step 1 of the tool for each batch | Values that neither the input data nor the title report gives, answers to checks, and corrections |

The counts quoted below come from the current LMS extract, active loans only. The title-report rules were worked out on 4 demo PDFs.

---

## General rules

- **Only active loans are processed.**
  - Before anything else, keep only COLLATERAL rows with **`Loan Status = A`**.
  - This drops cancelled loan accounts (`X`: ₹0 disbursed, with older dates and sometimes a different sanctioned amount) and closed loans (`C`).
  - After this filter, **every collateral has exactly one active loan account**, and its sanctioned amount and disbursal date are the same on every row.
  - Current extract: 1,150 applications and **1,312 collaterals**.
  - All other steps, including the borrower lists from CKYC, use only the applications that remain after this filter.
- **Batch size** = number of unique active Collateral IDs in the file. **A file can hold at most 1000 collaterals.** The current extract has 1,312, so it must be split into 2 files, each with its own Row 1.
- **One Collateral ID = one SI block** (Row 2 down to the last row below).
- **An application can have several collaterals, but a Collateral ID belongs to one application only** (116 applications have 2–8 collaterals; no Collateral ID appears under two applications).
  - Each collateral of an application gets its own SI block, with the same borrowers (BOR rows, from the application) and the full sanctioned amount of the loan.
  - The owners are worked out per collateral. They can be the same on every collateral, different, or overlapping, so IS_ASSET_OWNER, the owner count and IS_TPM can differ between the SIs of one application.
  - The SI blocks of one application are written one after the other.
  - If COLLATERAL ever lists a Collateral ID under two applications, that is a data error: the collateral is left out and reported until the LMS is corrected.
  - If two collaterals of one application have the same address (with different Global collateral Nos), both SIs get a warning: check that the same property is not recorded twice.
  - The same property can secure two applications only under two different Collateral IDs (same `Global collateral No`; see SI Column 13).
- **Date format everywhere is `yyyy-mm-dd`**, written as **text**. If Excel stores a date as a date, the concatenated output shows a serial number such as `38169`.
- **Output:**
  - The Excel file is the review copy. The upload file is a pipe-separated `.DAT` text file built from the same values.
  - Write every value as text, so codes, PINs and PANs keep their exact form.
  - No blank spacer rows.
- **Every row must have exactly its spec number of columns**, with empty columns still separated by `|`: Row 1 = 4, SI = 15, IMM = 27, BOR = 27, CHG = 11.
- **Column 1 of every row is its row type:** `FH`, `SI`, `IMM`, `BOR` or `CHG`.
- **Which source wins:** a value typed in the required-details file → input data (CKYC, COLLATERAL) → title report → default.
  - Read a title report only for values the input data doesn't have or that can't be used. The one value that always comes from it is the **type of mortgage**, which the input data doesn't hold.
  - **Property owners** follow the same rule: COLLATERAL first, with the title report checking them for every collateral that has one. The title report supplies the owners only when COLLATERAL has none, or adds one when the COLLATERAL shares show an owner is missing (see SI Column 4).
  - "Available" means present **and usable**:
    - not blank;
    - valid against the masters (e.g. a PIN that exists in the PIN master);
    - for details inside the free-text address, found cleanly by the parsing rules.

    Otherwise, treat it as missing.
- **The required-details file is keyed**, so typed values are matched back automatically:
  - sheet **Collaterals**: one row per collateral that needs a value, keyed by **Collateral ID**;
  - sheet **Borrowers**: one row per borrower that needs a value, keyed by **Application number + Neo CIF ID** (a value typed there is used on every SI of that application);
  - sheet **Check and correct**: differences between the input data and the title report side by side, title reports that may belong to another property, the owner decisions the tool made on its own, and empty rows to correct any other value.

  Cells to fill are yellow; the values the tool found are shown in grey and can be typed over. City and district can be typed as a name or a CERSAI code. Typing `BLANK` leaves an optional value empty.
- **Text cleaning (applies to every text column):**
  - Keep only the characters the field allows. Most text fields allow letters, digits, `-`, `_`, `.`, `/` and space; each column below notes its own rule.
  - Remove commas, brackets, `#`, `:` and other disallowed characters.
  - Remove dots after abbreviations (`No.` → `No`).
  - Collapse double spaces. Never leave two special characters side by side (e.g. `. ` or ` /`).
  - When text is too long, cut it at a word boundary, never mid-word and never by deleting spaces.

## Legal documents (title reports) — `Input data/Legal/`

- **One PDF per collateral**, named `<Application number>_<Collateral ID>.pdf` (e.g. `APPL00027326_COLL00266688.pdf`). An application with 2 collaterals has 2 PDFs with the same application number at the front.
- **The file name is the only link.** The PDFs contain no application number, loan account, collateral ID or PAN.
- **File names use the exact IDs from COLLATERAL.xlsx:** `APPL` + 8 digits and `COLL` + 8 digits (e.g. `COLL00266688`).
- **How to link a PDF to its rows:**
  1. Split the file name into the application number and the Collateral ID.
  2. Find that Collateral ID in COLLATERAL. It must match exactly; if COLLATERAL doesn't have it, flag the PDF (for example a typo in the name).
  3. Check that the collateral belongs to the application in the file name. A collateral belongs to one application only, so if COLLATERAL lists it under another application, flag the PDF as misfiled (rename it).

     The Legal folder keeps the PDFs of earlier days: a PDF of a collateral that is not in the current batch (filed earlier, or not active) is ignored, even when another collateral of the same application is in the batch.
  4. List the active collaterals that have no PDF. Their values come from the input data as normal; the type of mortgage and any remaining gaps go to the required-details file.
  5. **Check it's the right PDF** before taking any value from it (otherwise a misnamed PDF would fill gaps with another property's details):
     - "Loan applicant" ≈ the CKYC primary borrower;
     - owners (item 4) ≈ COLLATERAL `Owner Name`;
     - the flat/shop number in item 1 appears in COLLATERAL `Full Address`.

     The flat/shop check counts as failed only when the COLLATERAL address names a unit of its own.

     If 2 or more checks fail, hold the SI until someone answers `PDF OK` or `WRONG PDF` in the required-details file. While the SI is held, **no value is taken from that PDF**.

     **Reports swapped between two collaterals of one application:** these share the loan applicant and often the owners, so only the flat/shop number gives it away. If the unit in the PDF is not this collateral's but is the unit of another collateral of the same application (including one filed in an earlier batch), hold the SI whatever the other checks say, naming that collateral (rename the two files, or answer `WRONG PDF`). The owner comparison is also the owner check described in SI Column 4. Apart from the owners, these checks only verify the file; they never replace an input-data value.
- **What the report looks like:** a "TITLE REPORT" from the advocate with a header (Status, dates), a box with "Loan applicant" and "Property Owner", and a numbered table. The items used here:
  - **Item 1 — Full Description of the property:** flat/shop number, floor, area and unit, society/project, building, survey/Hissa/plot numbers, village, district (a PIN only sometimes). Used for any of these the input data lacks.
  - **Item 2 — Nature of immovable property:** Residential / Commercial. Used only for `PLOT` properties.
  - **Item 4 — Name of the owner:** the owners. Always read: it checks the COLLATERAL owners, supplies them when COLLATERAL has none, and adds an owner when the COLLATERAL shares show one is missing. When it simply names other owners, the COLLATERAL owners are kept and both lists are shown for review.
  - **Item 8 — Nature of Mortgage:** e.g. Equitable Mortgage ("Mortgage by deposit of title deeds" is also an equitable mortgage). Always used.

  Find items by their **label**, not their number: one law firm's reports have no item 6.
- **Watch out for:**
  - **Struck-through text.** One firm strikes out the search section and the Final Certificate, but the words are still in the PDF's text. Take the mortgage type from item 8 only.
  - **Other PIN codes** in the report: ARGFL's `400063` and the law firm's own. Look for the property PIN only inside item 1.
  - **Typos and variants:** `Commerical`, two spellings of the same village, curly quotes, double spaces, and words broken across lines (`Co- op`).
- **Not in the title report:** loan amount, mortgage (SI creation) date, borrower details (PAN, date of birth, gender, father's name, CKYC, CIN), and the CERSAI city/district/state codes.
- A detailed comparison of the four demo PDFs is in `notes i created to map rows/CERSAI_SI_batch_mapping_notes.md`, §15.

## Row 1 (written once per .DAT file) — FH, `introduction` sheet, 4 columns

- **Column 1 - FILE_HEADER** - value `FH`
- **Column 2 - FILE_TYPE** - value `SI_REGN`
- **Column 3 - NUMBER_OF_RECORDS** - number of collaterals (SI blocks) in **this file**, between 1 and 1000
- **Column 4 - FILE_DATE** - today's date, `yyyy-mm-dd`

(From here on, each collateral in the batch gets all of the rows below.)

## Row 2 — SI (`si` sheet), 15 columns

- **Column 1 - ROW_TYPE** - value `SI`
- **Column 2 - SERIAL_NUMBER** - 1 to N across the collaterals in this file. It must be unique in the file.
- **Column 3 - NUMBER_OF_BORROWERS** - count of unique `Neo CIF ID` for this collateral, **excluding `Customer Type = Guarantor`** (a guarantor is not a borrower; 34 collaterals have one; confirm this with compliance).
  - Counting in the COLLATERAL excel works: every collateral row lists all customers of its application, and the set is identical to CKYC.
  - This number **must equal the number of BOR rows written** for this collateral. Derive both from the same borrower list; never type it by hand.
- **Column 4 - NUMBER_OF_ASSET_OWNERS** - number of the collateral's owners who are **not** borrowers; `0` when every owner is a borrower.
  - **Owners come from COLLATERAL first** (decided 2026-09-30): the distinct `Owner Name` values on this collateral's active rows.
    - **Double-check the count** with `Percentage Share` (the shares must add up to 100%) and `Ownership Status` (`Single` = one owner, `Joint` = two or more). If they don't add up, list the collateral in Check and correct. In the current extract they always add up.
    - **One cell can hold two people** (`Kalaiselvi and Radhakrishnan Sankaranarayanan`, 100%, Single: 3 collaterals). Split it into two owners only when each part is a different borrower. Company names contain "and" too (`Jamson Machine and tools`, `OSNAR PAINTS AND CONTRACTS`), so a name that is not split and has no business word is only listed for review.
  - **The title report checks them.** Read its **item 4 "Name of the owner"** (e.g. `Mr. A & Mrs. B`, `A, B and C`). Split it on `,`, `&` and `and`, but keep company names such as `X AND COMPANY` whole, and keep `S/O ...` with the name before it; then remove `Mr.`/`Mrs.`/`Dr.`/`Smt.`. If the report's header box or item 12 names different owners from item 4, flag the report.
  - Compare the two lists, comparing names as described below:
    - **same owners** → use them (verified);
    - **the lists differ** → **use the COLLATERAL owners**, and show both lists in Check and correct, where the right owners can be typed. Title-report owner names are harder to read reliably than the COLLATERAL column;
    - **the COLLATERAL shares show an owner is missing** (they add up to less than 100%, or `Joint` with one owner) **and the title report names every COLLATERAL owner plus others** → add those others (the title report fills the gap), shown in Check and correct;
    - **COLLATERAL has no owners** (37 collaterals) → use the title report's owners, shown in Check and correct;
    - **no usable title report** → use the COLLATERAL owners, marked "not verified";
    - **neither source has owners** → typed in the required-details file.
  - Work owners out **per collateral**: the collaterals of one application can have the same owners, different owners, or some owners in common.
  - Match each owner to the borrowers kept in Column 3. An exact text match is not enough: in the LMS data only 798 of 1,636 owner names match a `Customer Name` exactly. Owner names carry `Mr.`/`Mrs.`/`Smt.`, leading spaces, different case and spelling variants (`MR. PREM MATA SEVAK MISHRA` vs `PREM MATASEVAK MISHRA`).
  - Before comparing, on both sides: upper-case; remove `MR`, `MRS`, `MS`, `SMT`, `SHRI`, `DR`, `M/S` and punctuation; collapse spaces; treat `PVT LTD` and `PRIVATE LIMITED` as the same, and `MOHD` / `MD` as `MOHAMMED`. Drop a relative's name after `S/O`, `D/O`, `W/O` (CKYC writes `SO`, `DO`, `WO`: `KAMALA DO HIMMATMAL` is compared as `KAMALA`, so she is not taken for her father).
  - Then compare the names **word by word**. A word of one name matches a word of the other when it is:
    - the same word, also written differently: sounding the same (`LAXMI` / `LAKSHMI`), with or without `-BEN`, `-BHAI` or `-AMMA` (`LATABEN` / `LATA`), or written as two words (`ANILKUMAR` / `ANIL KUMAR`);
    - an initial for it, on either side (`CHANDAN K SINGH` / `CHANDAN KAILASH SINGH`);
    - a close spelling (`PAREKH` / `PARIKH`).
  - **If each name has a word the other lacks, they are different people**, even when the surname and the father's or husband's name are the same. Relatives share those (`SUNANDA RAMCHANDRA SAWANT` is not `RAMCHANDRA GANPAT SAWANT`). A plain fuzzy score would call them the same and hide a third-party mortgage.
  - **The given names must correspond.** When one name only has extra words, the two given names must pair up. A wife's name usually contains her husband's given name and surname: `DEEPA RAVIRAJ HIREMATH` is not `RAVIRAJ HIREMATH` (her given name is Deepa); a missing middle name is fine (`ROHAN JOSHI` = `ROHAN MAHESH JOSHI`). Names can be written surname first (`SHAH RAGINI DHIRAJ`); a leading initial (`M GURU RAGHAVENDRA`) or `MOHAMMED` is not the given name.
  - **One borrower per owner, per property.** Owners listed separately are different people, so each borrower is linked to one owner of a collateral at most, best match first. When husband and wife both own a property and only the husband is a borrower, the wife cannot be linked to him: she is a non-borrower owner (third-party mortgage).
  - The result for each owner (nothing waits for an answer; the tool decides):
    - **the same person** (every word alike, or at least two alike and the rest initials or extra words, with the given names corresponding) → that borrower (1,450 LMS owners);
    - **similar names** (a close spelling, too few words alike, or the word order unclear) → taken to be that borrower (149 owners);
    - **given names differ** (a relative: the owner `GOPALAKRISHNAN` and the borrower `KAVITHA GOPALAKRISHNAN`) → a different person (3 owners);
    - **anything else** → a non-borrower owner (34).
  - The similar-name and relative decisions (142 collaterals) are listed in Check and correct. A `Y` or `N` typed there changes the decision, and one answer covers every collateral of the application where that owner appears.
  - A guarantor who owns the property counts here, because guarantors are not in Column 3.
- **Column 5 - NUMBER_OF_CONSORTIUM_MEMBERS** - `0` by default
- **Column 6 - SI_TYPE_ID** - take the type of mortgage from the collateral's title report, **item 8 "Nature of Mortgage"** (all 4 demo reports say `Equitable Mortgage` → `17`). The input data doesn't hold this, so it always comes from the title report. The required-details file overrides it.
  - In the `SI_SUB_TYPE_ID` sheet of CERSAI2.0_Masters, find the type in "SI Type Description" and take its "SI Sub Type ID / Transaction Sub Type ID".
  - Only look at rows where "Asset Category Description" = `Immovable` (IDs 17–21). `Conditional Sale` and `Other` also appear for movable and intangible assets (e.g. `Other` = 21, 27 and 29).
  - Valid values: 17 Equitable Mortgage, 18 Registered Mortgage, 19 Agreement to Create Mortgage (UUC), 20 Conditional Sale, 21 Other.
  - Never read it from the report's "Final Certificate" paragraph: one law firm strikes that paragraph out while a search is pending.
  - If there is no usable title report and nothing is typed, leave it blank: it is asked for in the required-details file, and the SI stays out of the `.DAT` file until it is typed (it is mandatory). No type is assumed (decided 2026-10-13).
- **Column 7 - SI_TYPE_OTHERS** - blank by default. It is **mandatory when Column 6 = 21 (Other)**; then take the description from the title report's item 8 wording, or from the required-details file (max 100 characters).
- **Column 8 - FINANCING_TYPE_ID** - financing type is "Sole" by default, so value `1`
- **Column 9 - SI_CREATION_DATE** - disbursal date.
  - Recommended: **CKYC `First Disbursal Date`**. It is one value per application, in `DD-MM-YYYY` with a 4-digit year, so convert it to `yyyy-mm-dd` (e.g. `01-07-2026` → `2026-07-01`).
  - The COLLATERAL `Disbursal Date` (from any active row; it is the same on all of them) also works. It is actually the loan booking date and has a 2-digit year (`01-JUL-26` → `2026-07-01`).
  - The two dates differ by 1–45 days in 30 applications. Confirm which one matches the mortgage date.
  - The title reports don't contain this date: they are written before disbursal.
- **Column 10 - TOTAL_SECURED_AMOUNT** - sanctioned loan amount from any active row of this collateral. After the active-only filter it is the same on every row (checked: no collateral has two different values).
  - If its active rows ever show two different sanctioned amounts, leave it blank and ask for it in the required-details file (no amount is assumed).
  - Digits only (max 13), greater than 0.
- **Column 11 - ENTITY_MIS_TOKEN** - built from `Application number` + `Collateral ID`.
  - The maximum is **20 characters** (letters and digits only), and a plain concatenation is 24.
  - Use `A` + last 8 digits of the application number + `C` + last 8 digits of the Collateral ID. For example, `APPL00027326` + `COLL00266688` becomes `A00027326C00266688` (18 characters).
  - Alternative: the Collateral ID alone (12 characters, already unique).
- **Column 12 - NARRATION** - optional; blank by default. `NA` is technically allowed but carries no information. If something useful is wanted, put `LAN <Loan Account #>` (max 100).
- **Column 13 - TYPE_OF_CHARGE** - `FIRST CHARGE` by default (letters and spaces only, max 20).
  - 24 properties (same `Global collateral No`) secure two active loans and may need a second or pari passu charge: for these, TYPE_OF_CHARGE is left blank and asked for in the required-details file (no charge is assumed).
- **Column 14 - IS_TPM** - `1` if Column 4 > 0 (some owner is not a borrower = third-party mortgage), otherwise `0`.
  - When it is 1, CERSAI also needs **ASO (asset owner) rows**, which are not in scope yet. These collaterals are left out of the `.DAT` file and listed, to be filed by hand.
- **Column 15 - BATCH_REF_NUMBER** - optional. Either leave it blank, or write **exactly 20** letters and digits: `ARGF` + today `yyyymmdd` + last 8 digits of the Collateral ID, e.g. `ARGF2026090100266688`. Underscores and hyphens are not allowed.

## Row 3 — IMM (`immovable_asset` sheet), 27 columns

Property values come from the input data first: COLLATERAL `Property Type`, `Property Pincode` and `Carpert Area`, plus the details parsed from `Full Address`. Read the collateral's title report only for values the input data doesn't have or that can't be parsed cleanly. A value typed in the required-details file always overrides.

- **Column 1 - ROW_TYPE** - value `IMM`
- **Column 2 - ASSET_CATEGORY_ID** - `1` by default (Immovable)
- **Column 3 - ASSET_TYPE_ID** - COLLATERAL `Property Type` (never blank), looked up in the `ASSET_TYPE_ID` sheet of CERSAI2.0_Masters.
  - Only look at rows with "Asset Category ID" = `1`. `Other` also exists for movable (7) and intangible (14) assets.
  - A text lookup only works for `RESIDENTIAL` → `1` and `COMMERCIAL` → `2` (compare case-insensitively).
  - The master has no `INDUSTRIAL` (37 collaterals), `MIXED USAGE` (40), `PLOT` (35) or `PG` (1). Map them as follows:
    - INDUSTRIAL → `3`
    - MIXED USAGE → `3`
    - PG → `1`
    - PLOT → by the plot's use, from title report **item 2 "Nature of immovable property"**: `Residential` → `1`, `Commercial` (also spelt `Commerical`) → `2`; otherwise (no usable title report, or another wording) it is left blank and asked for in the required-details file. The same for an unknown `Property Type`. No type is assumed.
- **Column 4 - ASSET_TYPE_OTHERS** - **blank unless Column 3 = 3.** When it is 3, give a short description, e.g. `Industrial`, `Mixed Usage`, `Plot` (max 50).
- **Column 5 - ASSET_SUB_TYPE_ID** - derive the sub-type from the unit word in the LMS address (or, when the address has none, in title report **item 1**):
  - Flat / Shop / Office / Unit / Gala in a building → "Structure without Land"
  - House / Bungalow / Row house → "Structure with Land"
  - Plot / land only → "Land without Structure"

  When neither says, the sub-type is asked for in the required-details file. Then find the ID in the `ASSET_SUB_TYPE_ID` sheet. The same description exists under every asset type, so filter by **Asset Type ID = Column 3**:
  - Residential (1): 1 with land, 2 without land, 3 land only, 20 unidentified
  - Commercial (2): 4, 5, 6, 21
  - Other (3): 7, 8, 19, 22

  Example: an office unit in a commercial building = `5`. (`2` belongs to Residential, so it is invalid with a Commercial asset type.)
- **Column 6 - ASSET_UNIQUE_ID** - optional. Leave it **blank**, not `NA`, because `NA` would be stored as the asset's ID. Optionally use COLLATERAL `Global collateral No` (e.g. `CMS00260877`), or the title-deed registration number from title report item 5.
- **Column 7 - ASSET_DESCRIPTION** - **mandatory**, max 100, cleaned.
  - Build it from the input data: `<property type> <unit kind> <unit number> <project>`, e.g. `COMMERCIAL UNIT 21 YASHODHAM BUSINESS CSL`.
  - Fill any missing parts from title report item 1 (e.g. `Shop 13B Ground Floor Devdaya Park Co-op Hsg Soc Ltd`).
  - With no unit number, use the plot number instead: `PLOT NO 45`.
- **Column 8 - SURVEY_NUMBER** - from the LMS address: the numbers after `Survey No.`, `S. No.`, `Sy. No.`, `CTS No.`, `C.S. No.`, `Gat No.` or `Khasra No.`.
  - When the address has none, take them from title report item 1. 39% of active addresses have neither a survey nor a plot number, so this is the title report's most common use after the type of mortgage.
  - Separate multiple numbers with `^`: `Survey No. 149/1/3, 150/6, 152/5` → `149/1/3^150/6^152/5`.
  - If old and new survey numbers are both given, use the new one with its Hissa: `Old S. No. 260(Pt) and New S. No. 12 and Hissa No. 2` → `12/2`.
  - Ignore numbers in a description of the boundaries (`bounded on the West by Plot No. 16 …`): they belong to the neighbouring plots. The same applies to Column 9 and Column 12.
  - **At least one of Column 8 and Column 9 must be filled.**
- **Column 9 - PLOT_NUMBER** - `Plot No.` (or `P.No.`) in the LMS address; otherwise from title report item 1: `Plot No.`, or the `FP/PF No.` of a town-planning scheme (`PF No. 4 of TP` → `4`). Max 20 characters. Leave it blank if there is no plot number (not `NA`).
- **Column 10 - ASSET_AREA** - COLLATERAL `Carpert Area`. Optional. Numbers only, max `99999.99`.
  - Its unit isn't stated in the LMS; it is assumed to be square feet. **Confirm this with the LMS team**: square metres vs square feet changes the value about 10.8 times.
  - When it is blank (10 collaterals), take the area from title report item 1: the number after `adm.` / `admeasuring` (e.g. `adm. 60.90 Sq. Mtrs., Carpet area` → `60.90`), as the report states it.
  - When both exist, convert the title report's area to square feet; if it is more than 10% away from both the LMS carpet and built-up areas, keep the LMS value and show the two side by side for checking.
- **Column 11 - ASSET_AREA_UNIT** - the **ID** from the `AREA_UNIT` sheet, following the area's source:
  - area from the LMS → `6` (Square Feet);
  - area from a title report → the unit written next to it: `Sq. Mtrs.` / `sq.mtr` → `7`, `Sq. Ft.` / `Sq. Fts.` → `6`, `Sq. Yds.` → `8`, `Acre` → `1`, and so on.

  It is **mandatory when Column 10 has a value**, and blank when Column 10 is blank.
- **Column 12 - HOUSE_NUMBER** - the unit number in the LMS address (`Office No. 21` → `21`; also `House bearing No.`, `Property No.` and `Property bearing No.`); about 72% of addresses have one. A number marked "Old" (`Old Property No. 121, New Property No. 1777`) is used only when there is no other.
  - When the address has none, use the unit number in title report item 1: `Flat No. 1102` → `1102`, `Shop No. 13B` → `13B`, `Flat No. C-3002` → `C-3002`.
  - Required when the sub-type is "Structure with Land" or "Structure without Land" (1, 2, 4, 5, 7, 8). When the sub-type is not known yet (and the property is not a `PLOT`), ask for both together.
  - Letters, digits, `-`, `/` and space only; max 20.
  - For several units, see "Questions and answers" below.
- **Column 13 - FLOOR_NUMBER** - optional. From the LMS address, otherwise title report item 1: `11th Floor` → `11`, `Ground Floor` → `0`, `Basement` → `-1`. A whole number from −3 to 100. Blank if unknown, or if the address names more than one floor (`Ground and First Floor`).
- **Column 14 - BUILDING_NAME** - optional. From the LMS address; otherwise from title report item 1 when it names a building or tower (e.g. `Building No. 3 known as 'Dev Daya Park'` → `Dev Daya Park Building No 3`). Max 50.
- **Column 15 - PROJECT_NAME** - **mandatory**; it cannot be left blank.
  - From the LMS address (e.g. `Yashodham Business CSL`).
  - When the address doesn't give it, from title report item 1: `project known as …` first, otherwise `Society known as …` (e.g. `Aaradhya Parkwood`, `Devdaya Park Co-op Hsg Soc Ltd`).
  - Max 50.
  - If neither gives one, it is asked for in the required-details file. If no project exists (e.g. a village plot), type the colony or village name.
- **Column 16 - STREET_NAME** - optional. From the LMS address; otherwise from title report item 1 when it names a road (e.g. `Pokharan Road No 1`). Max 50; letters, digits, `-`, `/` and space only. Cut at a word boundary (e.g. `Aba Karmarkar Road`), never by removing spaces.
- **Column 17 - POCKET** - optional; blank unless typed in the required-details file. Max 20.

**For columns 18 to 22:**

1. **PIN code** = COLLATERAL `Property Pincode` of this collateral. It is already a separate column; cross-check it with the 6-digit PIN at the end of `Full Address`.
   - Only if it is blank or not in the PIN master (8 collaterals), use the PIN in title report item 1, when there is one (only 1 of 4 demo reports has one); otherwise it is asked for in the required-details file.
   - Look for that PIN **only inside item 1**: every report also contains ARGFL's PIN and the law firm's PIN elsewhere.
2. **Use the CERSAI2.0_Masters `PIN_CODE` sheet**, not `crs2_addrss_mstr_pincd_analysis_20260416` → `effective_master`. The masters file is the newer official list (v29.3, updated 04-09-2026). It already contains every `effective_master` pair plus 30 more.
3. Search the PIN and take its **District Code**.
   - If the PIN is still not found in the master, flag it.
   - If the PIN appears with **more than one District Code** (89 collaterals), pick the district named in title report item 1 (`Taluka and District …`) or in the address; otherwise ask for it (the district can be typed by name).
4. **State Code:** take it directly from the `DISTRICT` sheet (District Code → State Code). No state-name matching is needed. (Name matching would fail anyway: `effective_master` has `MAHARASHTRA` while the STATE sheet has `Maharashtra`, so 0 of 36 names match exactly.)
5. **City Code:** in the `CITY` sheet, keep only rows with **our District Code**.
   - Then find which of those city names appears in the property address, and take the **longest match** (`GOREGAON EAST` beats `MALAD`).
   - Before matching, treat `(E)`/`(W)` and `EAST`/`WEST` as the same.
   - Don't just take the city word from the end of the address (`…, Mumbai, Maharashtra- 400063, India`). That is the LMS city and is often less specific: use it only when no more specific city of the district is named, or as a fallback if that name exists in the district.
   - Ignore a "city" named like the state: the CITY master has a city called `UTTAR PRADESH` in Ghaziabad district, which the state name at the end of every UP address would otherwise match.
   - Anything still unmatched (17 collaterals) is asked for in the required-details file, where the city can be typed by name or code.
   - City names repeat across districts (8,066 of them), so **never pick a city without the district filter**.
6. **Locality:**
   - First choice: the area name just before the city in the LMS address (e.g. `Dindoshi Goregaon East`).
   - Next: the area or village named in title report item 1 (e.g. `Vartak Nagar`, `Village Mahajanwadi`).
   - Last: the required-details file.

- **Column 18 - LOCALITY** - value = locality. **Mandatory**, max 50.
- **Column 19 - CITY** - value = City Code, the number only (e.g. `187602`, never `Goregaon (E)`)
- **Column 20 - DISTRICT** - value = District Code (e.g. `10680`)
- **Column 21 - STATE** - value = State Code (e.g. `21`)
- **Column 22 - PIN_CODE** - value = PIN code (6 digits)
- **Column 23 - COUNTRY** - `IND`: the batch format description says "as per master" for this row, and the COUNTRY master's code for India is `IND`.
- **Column 24 - LATITUDE_LONGITUDE_1** - blank
- **Column 25 - LATITUDE_LONGITUDE_2** - blank
- **Column 26 - LATITUDE_LONGITUDE_3** - blank
- **Column 27 - LATITUDE_LONGITUDE_4** - blank. These 4 columns must still be written as empty values, so the IMM line ends with `IND||||`.

## Row 4 to Row (4 + no. of borrowers − 1) — BOR (`borrower` sheet), 27 columns

In these rows, most values come from the CKYC excel. Join CKYC to the working collateral on application number.

- CKYC has **one row per customer per ID document** (PAN, GST, Udyam…), so first **group by `Neo CIF ID`**: one BOR row per customer.
- Take the PAN from that customer's row where `Identification Type = PAN`.
- Leave out Guarantors, as in SI Column 3.

**Which group of columns to fill** depends on the **Borrower Type (Column 3)**, not on `Applicant Type`:

- If Column 3 is **not `IND`**, fill columns 7–11 and leave 12–19 blank.
- If Column 3 is **`IND`**, fill columns 12–19 and leave 7–11 blank.

`Applicant Type` is unreliable here: 25 sole proprietorships and 2 private limited companies are tagged `individual`, and 1 individual is tagged `non_individual`.

- **Column 1 - ROW_TYPE** - value `BOR`
- **Column 2 - SERIAL_NUMBER** - the i-th borrower, 1 to no. of borrowers. Primary borrower first.
- **Column 3 - BORROWER_TYPE** - CKYC `CONSTITUTION` → code from the `BORROWER_ASSET_OWNER_TYPE` sheet. The LMS text does not match the master text, so use this fixed mapping instead of a text lookup:
  - Individual → `IND`
  - NO PAN → `IND`
  - Sole Proprietorship Firm → `SPR`
  - Partnership Firm → `PRF` (not `COM`, which means Indian Company)
  - Limited Liability Partnership → `LLP`
  - Private Limited Company → `COM`
  - Public Limited Company → `COM`
  - Hindu Undivided Company → `HUF`
  - Private Trust → `TRS`
  - anything else → flag for review
- **Column 4 - IS_ASSET_OWNER** - `1` if this borrower is an owner of this collateral, else `0`.
  - CKYC has **no owner information**. Use the owners decided in SI Column 4 (COLLATERAL owners, checked against title report item 4). Match them to this borrower's `Customer Name` with the same name comparison.
  - It is decided **per collateral**: a borrower of an application with several collaterals can own one of them and not another, so the same BOR row can have `1` in one SI block and `0` in the next.
  - Check: the number of borrowers with `1` + SI Column 4 = total owners of the collateral.
- **Column 5 - BORROWER_UID_TYPE** - blank (must be empty)
- **Column 6 - BORROWER_UID_VALUE** - blank (must be empty)
- **Column 7 - BORROWER_PAN** - PAN from CKYC, when Column 3 is not `IND`. Format: 5 letters, 4 digits, 1 letter.
- **Column 8 - BORROWER_CKYC_NUMBER** - **required when the non-individual has no PAN** (431 sole proprietorships today); otherwise blank.
  - It is a 14-digit number. It is **not in the CKYC excel** despite the file's name (a `KYC Identification Number` row holding a GST-style value doesn't count), so take it from the required-details file.
- **Column 9 - BORROWER_NAME** - CKYC `Customer Name`, when Column 3 is not `IND`.
  - Clean it: `&` → `AND`; remove brackets and dots (`JOGARAM PUROHIT (HUF)` → `JOGARAM PUROHIT HUF`). Max 100.
- **Column 10 - BORROWER_REGISTRATION_DATE** - CKYC `Incorporation Date`, only when Column 3 is not `IND`.
  - It is `DD-MON-YY` with a **2-digit year**, so convert it carefully: `01-JUL-04` → `2004-07-01`.
  - If `20YY` would be in the future, use `19YY`.
- **Column 11 - BORROWER_REGISTRATION_NUMBER** - CIN (21 characters) when Column 3 = `COM`; LLPIN when Column 3 = `LLP`. It is **mandatory for those two** and blank for everyone else.
  - Source: the CKYC row with `Identification Type = CIN No` (only 1 exists today); otherwise the required-details file (143 borrowers). An LLPIN is written without its hyphen (`AAB-1234` → `AAB1234`). Title reports don't contain it.
- **Column 12 - INDIVIDUAL_PAN** - PAN from CKYC, when Column 3 = `IND`
- **Column 13 - INDIVIDUAL_CKYC_NUMBER** - **required when the individual has no PAN** (5 today: 4 "NO PAN" plus 1 other); otherwise blank. 14 digits, from the required-details file.
- **Column 14 - GENDER** - `M`, `F` or `T` (`GENDER` sheet), when Column 3 = `IND`. It is **required for individuals**. Take it from the CKYC excel's **`Gender`** column (`Male` → `M`, `Female` → `F`; added 2026-10-09: the CKYC table has it, the current extract does not yet). If it is blank or the column is missing, it is asked for in the required-details file, where `Male`/`Female` are accepted too.
- **Column 15 - INDIVIDUAL_NAME** - CKYC `Customer Name`, when Column 3 = `IND`. Letters and spaces only (e.g. `SARVES .` → `SARVES`); max 50.
- **Column 16 - FATHER_MOTHER_NAME** - father's or mother's name, when Column 3 = `IND`.
  - It is **required for individuals** and **not in the CKYC excel**, so take it from the required-details file.
  - Don't build it from the middle name. The middle name is sometimes `WO` ("wife of").
- **Column 17 - DATE_OF_BIRTH** - CKYC `Date Of Birth`, when Column 3 = `IND`.
  - It is `DD-MON-YY` with a 2-digit year. Use `20YY` only if that makes the person at least 18 today; otherwise use `19YY` (e.g. `11-JAN-51` → `1951-01-11`).
  - Python's default parsing would give `2051` for 540 borrowers.
- **Column 18 - MOBILE_NUMBER** - CKYC `Mobile No`, when Column 3 = `IND`. Remove the `+91--` prefix so exactly 10 digits remain. If CKYC has none, COLLATERAL `PHONE_NUMBER`, if it is 10 digits (landline numbers are left out).
- **Column 19 - EMAIL** - CKYC `Email ID`, when Column 3 = `IND`. Optional.
  - Trim spaces. Leave it blank if it breaks the rule: one `@`, a dot after the `@`, only letters, digits, `_` and `.` (**no hyphen**), max 50. If the CKYC email breaks it, COLLATERAL `EMAIL_ADDRESS` is used when valid.

As in Row 3 for the property, each borrower's address goes in their own row:

- **Which address:** 40 customers have more than one address in CKYC, and CKYC doesn't say which type each one is. Take the address from COLLATERAL `Customer Address` using `ADDRESS_TYPE`:
  - individuals: `ResidentialAddress`, then `PermanentAddress`, then `OfficeAddress`;
  - non-individuals: `OfficeAddress`, then `AlternateBusinessAddress`, then `ResidentialAddress`;
  - if COLLATERAL has none, the first CKYC `Full Address`.
- Remove the ending `, <City>, <State>- <PIN>, India`, because city, state and PIN have their own columns. Then clean the text (no commas, dots, brackets…).
- **Column 20 - ADDRESS_LINE_1** - the address, up to 100 characters. Cut at a **word boundary**, not at exactly 100 characters.
- **Column 21 - ADDRESS_LINE_2** - if the address is longer than 100 characters, the rest goes here (max 100, cut at a word boundary); otherwise blank.
- **Column 22 - ADDRESS_LINE_3** - if it still doesn't fit, the rest goes here (max 100); otherwise blank. (After removing the city/state/PIN ending, no borrower address in the current data needs more than 2 lines.)
- **Column 23 - CITY** - City Code. This column is **mandatory**. Use the same steps as Row 3, with the borrower's PIN and address.
- **Column 24 - DISTRICT** - District Code (same steps as Row 3). The borrower's PIN is the 6 digits before `, India` at the end of the address.
- **Column 25 - STATE** - State Code
- **Column 26 - PIN_CODE** - PIN code
- **Column 27 - COUNTRY** - `IN`. The batch format description gives `"IN"` for this field; it does not point to the COUNTRY master (only the IMM row does, which is why IMM uses `IND`).

## Questions and answers

**1. Is PAN compulsory? What about gender and father's name?**

- **PAN alone is not compulsory**, but every borrower needs **either a PAN or a 14-digit CKYC number**. 436 current borrowers have no PAN (431 sole proprietorships, 4 "NO PAN", 1 individual), so they need a CKYC number from the required-details file.
- **Gender, father's/mother's name and date of birth are required for every individual borrower** ("Conditional" in the spec means required when the borrower type is Individual).
- None of them is needed for non-individuals.
- Father's/mother's name is **not in the CKYC excel** (or in the title reports), so it is filled in the required-details file (or the LMS team adds it to the CKYC query). Gender comes from the CKYC `Gender` column; only when it is blank is it typed.

**2. What if the full address lists two flats under a single Collateral ID?**

This happens in **37 collaterals** today (e.g. `Flat No. 1301 & 1302`, `Shop No. 18 To 25`). The title report's item 1 normally lists the same units, so the same rule applies to it.

**Recommended:**

- Keep **one SI block with one IMM row**. One Collateral ID is one mortgaged security.
- **Column 12 HOUSE_NUMBER:** join the numbers with `/`, e.g. `1301/1302` or `D-11/D-12` (only `-`, `/` and space are allowed; max 20). If that is longer than 20 characters, write the first unit here and list every unit in **Column 7 ASSET_DESCRIPTION** (e.g. `RESIDENTIAL FLATS 1301 AND 1302 ACROPOLIS`).
- **Column 13 FLOOR_NUMBER:** the floor if all units are on one floor; otherwise leave it blank (it is optional).
- **Column 10 ASSET_AREA:** the combined area of all the units: the LMS area for the collateral, or the title report's area when the LMS has none.

If the legal team treats each flat as a separate mortgage, it should be split into separate collaterals in the LMS; the automation should not split it. Also confirm whether CERSAI accepts more than one IMM row under one SI.

**3. What if a collateral has no title report, or the PDF can't be read?**

- It is listed in the Issues sheet of the working and final Excel files.
- The input data is used as normal, and the owners from COLLATERAL are marked "not verified". SI Column 6 (type of mortgage) is asked for in the required-details file, as are any gaps the title report would have filled (for example a missing survey number) are asked for there.
- A scanned PDF with no text layer is handled the same way until OCR is added.

**4. What if the title report and the input data disagree (e.g. owners or flat number)?**

- **Owners:** the COLLATERAL owners are used and both lists are shown in Check and correct. The title report adds owners only when the COLLATERAL shares show one is missing and the report names every COLLATERAL owner plus others.
- **Anything else:** the input data is used; the title report is only read for values the input data doesn't have. The two are compared only in the right-PDF check.
- **Differences that matter** (owners, flat/unit number, floor, survey and plot numbers, area beyond 10%, property type, PIN, district) are shown side by side in the required-details file's Check and correct sheet, with the value that will be used.
- If 2 or more right-PDF checks fail, the PDF may be saved under the wrong name, so hold the SI until someone confirms it; nothing is taken from the PDF meanwhile. A single failure is shown as a warning. A PDF whose flat/shop number belongs to another collateral of the same application is held too.

**5. What if one application has several collaterals?**

- Each collateral gets its own SI block, one after the other, each with the application's full sanctioned amount and the same BOR rows (the borrowers belong to the application).
- The owners are decided per collateral, so IS_ASSET_OWNER, the owner count and IS_TPM can differ between the blocks. For example: a flat owned by husband and wife, a shop owned by the husband alone, and a plot owned by the husband and his mother (who is not a borrower). Here only the plot is a third-party mortgage and is left out; the flat and the shop are filed. In the current extract, IS_ASSET_OWNER differs between the SIs of 54 of the 116 applications with several collaterals.
- Family members' names overlap (a wife's name usually contains her husband's), so each owner is matched to the borrower whose given name corresponds, and each borrower to one owner per property (see SI Column 4).
- Each collateral has its own title report, named with its own Collateral ID. If two of them are swapped, the flat/shop check catches it (see "Legal documents").
- Borrower values typed in the required-details file (gender, father's/mother's name, …) are typed once per application and used for all its collaterals.
